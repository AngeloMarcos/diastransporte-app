# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Dias Transporte" — transfer/booking site + dispatch back office for São Luís ↔ Lençóis Maranhenses (MA) routes, built with **TanStack Start** (SSR React). One app: the public storefront (`/`, `/transfers`, `/frota`, `/contato`, legal pages), the customer area (`/auth`, `/carrinho`, `/minhas-viagens`), the driver panel (`/motorista`) and the admin/dispatch panel (`/admin`). It is the merge of two former systems (the storefront "wander-book-craft" and the dispatch app "car-fleet-co"); both old repos are frozen.

**Production**: `https://www.diastransporte.site`, self-hosted on a Hostinger VPS (`179.197.74.90`), Docker Compose (`app` + Postgres 16 `db` + `caddy` for HTTPS + `autoheal`) in `/opt/diastransporte-app`, compose file `docker-compose.staging.yml`. There is no Lovable / Supabase any more — that backend and its code were removed. The old stacks (`/opt/dias-transporte`, `/opt/car-fleet-co`) are stopped, volumes kept, and can be deleted once the owner says so.

## Commands

```sh
npm install                          # node_modules is not committed
npm run dev                          # vite dev server (needs DATABASE_URL + SESSION_SECRET, see .env.example)
npm run build                        # production build (vite + nitro, node_server preset)
npm run lint                         # eslint (flat config)
npm run test                         # vitest — unit tests for pure logic only
npx tsc --noEmit -p tsconfig.json    # typecheck (no npm script)
```

Before pushing, always run typecheck + lint + tests + build. `tsconfig.json` is strict (`noUncheckedIndexedAccess`, `noPropertyAccessFromIndexSignature`, `exactOptionalPropertyTypes`), so index into `Record<string, T>` with bracket notation and treat indexed access as possibly `undefined`.

**Tests**: Vitest (`vitest.config.ts`, separate from `vite.config.ts`). Pure logic only — pricing/period rules, validation, WhatsApp/lead/invite helpers, SEO, security helpers, cart. No e2e suite against production: tests that complete a booking would write real rows. Verify server behaviour against the live site with read-only calls or clean up the rows you create.

**Windows CRLF gotcha:** checkouts on Windows often have CRLF endings; if `eslint` reports a wall of `Delete '␍'`, run `npx eslint --fix <file>`. Commit only the files you meant to change. Edit scripts that match multi-line strings must normalise `\r\n` first.

## Architecture

**Routing**: TanStack Start file-based router (`src/routes/README.md`). `src/routeTree.gen.ts` is generated by the build — never hand-edit. `_authenticated/route.tsx` is a pathless layout whose `beforeLoad` redirects to `/auth` without a session (`admin`, `minhas-viagens`, `motorista` live under it).

**One data layer**: screens call `src/lib/dados.ts`, never SQL. Each function there is a thin wrapper over a `createServerFn` in `src/lib/vps/*.functions.ts` (`dados.functions.ts` storefront/admin, `dados-despacho.functions.ts` dispatch, `leads.functions.ts`, `convite.functions.ts`, `sessao.functions.ts`). The `*.server.ts` files (`db.server.ts` = `postgres` pool, `auth.server.ts`, `auditoria.server.ts`, `convites.server.ts`, `uploads.server.ts`, `despacho-sync.server.ts`) are server-only: load them with `await import(...)` **inside** handlers, never at module top level (route files and `*.functions.ts` ship to the client bundle; the TanStack import-protection plugin fails the build otherwise, including for `typeof`-style type aliases of server functions). There is no RLS: **authorization is enforced in the server functions** (`exigirUsuario` / `exigirAdmin` / `exigirMotorista`), not by the database. New feature = new server function + wrapper in `dados.ts`.

**Database**: Postgres, schema in `db/migrations/*.sql` (run by `db/migrate.mjs`, idempotent, tracked in `public.schema_migrations`; runs with the DDL role `diasapp_migration`, the app connects as `dias_app` with CRUD-only grants — new tables get grants through default privileges). Core tables: `rotas`, `agendamentos` (site bookings), `conteudo_site` (CMS blocks), `frota_veiculos`/`frota_galeria`, `usuarios`/`sessoes`/`convites`, `leads`, `auditoria` (append-only, `REVOKE`d for UPDATE/DELETE), and the dispatch set `pedidos`, `pedidos_historico`, `pedidos_notas_internas`, `fornecedores` (drivers), `empresas_clientes`, `canais_venda`, `categorias_veiculo`. Test a migration before applying: run it inside `BEGIN … ROLLBACK` on the server.

**Pricing is never trusted from the client**: `agendamentos.valor` is computed by a DB trigger from `rota_id` + `carro` + `periodo`, and `periodo` (dia/noite, night = 18:00–04:59) is derived from `hora` by the same trigger (`src/lib/periodo.ts` mirrors it). `NovaReserva` deliberately has no `valor`. A site reservation also creates a dispatch `pedido` (`despacho-sync.server.ts`, best-effort, outside the booking transaction) and is linked to it by `agendamentos.pedido_id`; triggers (migration 0018) keep the two statuses coherent in both directions (cancel reservation → cancel pedido; release/assign/finish pedido → confirm/complete reservation). The DB also refuses a second active reservation for the same user + route + date + time + car (`ux_agendamentos_sem_duplicata`). The old driver model (`agendamentos.motorista_id`) is gone; drivers are `fornecedores` assigned to `pedidos`.

**Auth**: own bcrypt + cookie sessions. The cookie `dias_sessao` is `HttpOnly`, `Secure` when `APP_URL` is https; only the SHA-256 of the token is stored in `public.sessoes`. Login locks an account for a while after 5 wrong passwords. There is **no e-mail provider**: no password-reset e-mail, no confirmation e-mail. Drivers get an invite link (7 days, single use, `/convite/<token>`) generated by the admin; forgotten customer passwords are reset by an admin in "Usuários e acessos" (the login page points people to WhatsApp). `useAuth()` exposes `{ user, isAdmin, isMotorista, carregando }`.

**Cart & checkout** (`carrinho.ts` + `reserva.ts`): `localStorage` cart, items carry `rotaId` but never a price; checkout calls `criarReservas()`.

**Uploads**: `enviarImagem()` re-encodes the photo to WebP (max 1920px, EXIF stripped — `lib/imagem.ts`) in the admin's browser, then POSTs to `/api/uploads` (`src/routes/api/uploads.ts`, admin only) which writes to `UPLOADS_DIR` (Docker volume); `/api/uploads/$arquivo` serves it. Photos shipped in the repo live in `src/assets/*.webp` (bundled) and `public/frota/*.jpeg` (the DB references these paths — keep the file names).

**HTTP hardening** (`src/server.ts`, `src/lib/seguranca.ts`): security headers on every response (CSP with `frame-ancestors 'none'`, HSTS only over https), 120 write requests/min per IP (429 + Retry-After), canonical/sitemap/robots/og:image built from `X-Forwarded-Proto/Host` (Caddy sets them — keep that). Public lead form is protected by a honeypot and 5/hour per IP hash. `src/server.ts` also turns h3-swallowed SSR errors into `src/lib/error-page.ts`.

**Health**: `GET /healthz` returns `{ok}` (200, or 503 when the database does not answer within 3 s) for external uptime monitors; the Docker healthcheck deliberately uses `/`, which keeps returning 200 with static fallbacks while the database is down (restarting the app would not help).

**SEO**: canonical link per public page, JSON-LD (`lib/seo.ts`), dynamic `sitemap.xml` / `robots.txt`. Company facts (hours, WhatsApp, cancellation window) live once in `EMPRESA` (`src/data/rotas.ts`); `razaoSocial`/`cnpj` are optional and shown on the legal pages only when filled.

**Styling**: Tailwind v4 (CSS-first, `src/styles.css`), fixed dark theme (oklch tokens) — no light/dark toggle. Fonts are self-hosted (`@fontsource-variable/inter|oswald`); no third-party requests. shadcn/radix components in `src/components/ui/` are normal source.

## Deploy & operations

See `.claude/skills/deploy/SKILL.md` (ship a change), `vps-deploy` (operate the server), `vps-db` (database, backups). Short version: push to `main`, then on the VPS `git fetch && git reset --hard origin/main`, `docker compose -f docker-compose.staging.yml build app`, `docker compose … run --rm -T app node db/migrate.mjs`, `up -d --no-deps app`. Caddyfile is a single-file bind mount: after it changes on disk, `up -d --force-recreate caddy` (a plain `caddy reload` reads the stale inode). Backups: `infra/backup-postgres.sh` nightly (systemd timer, 14-day retention); `infra/testar-restauracao.sh` proves a restore works — run it before risky changes.

## External integration points

Nothing talks to an outside system through a formal API: WhatsApp is only `wa.me` deep links (`lib/whatsapp.ts`), there is no e-mail/SMS provider, no online payment, and no inbound API. A new integration (payment webhook, channel manager, n8n) needs a route under `src/routes/api/` with its own auth (`comparaSegura()` in `vps/auth.server.ts` exists for shared-secret checks) and should read/write through server functions, not raw SQL from route code. Lead notification to the owner is wired but off: set `LEADS_WEBHOOK_URL` (+ `LEADS_WEBHOOK_SECRET`) to enable.
